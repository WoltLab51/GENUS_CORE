# GENUS_CORE Decisions v0.4
Status: active for v0.4.3 Artifact Contract and Boundary Wording Alignment
Decision blocks for Passive Boundary Relevance.

## Decision 0039 - v0.4.0 finalizes Passive Boundary Relevance spec-only

Decision:

v0.4.0 accepts `PASSIVE_BOUNDARY_RELEVANCE_SPEC_v0.4.0.md` as the Passive
Boundary Relevance spec baseline without adding runtime implementation.

Reason:

Boundary Relevance is the next GENUS layer after passive transition preview,
but it must be specified before it is built. The spec fixes the difference
between relevance and evaluation, removes `no_boundary_evaluation_possible`
from the planned shape, and keeps permission, policy, allow/block, decision,
reaction, and memory write out of scope.

Impact:

Package version becomes `0.4.0`; `SCHEMA_VERSION` remains
`genus.foundation.v0.0.1`. No runtime package, class, function, CLI command,
SQLite table, sentence type, worker, LLM, reaction, memory write, transition
candidate, constraint decision, GraphDB, or RuntimeShape is introduced.

## Decision 0040 - v0.4.1 activates narrow Passive Boundary Relevance preview

Decision:

v0.4.1 implements `PassiveBoundaryRelevancePreview`,
`PassiveBoundaryRelevanceReport`, `build_passive_boundary_relevance_preview`,
and `create_passive_boundary_relevance_report` in
`genus_core.passive_boundary_relevance`.

Reason:

GENUS may now describe passive boundary relevance downstream of belief,
passive metrics, and passive transition preview, but it must not evaluate
boundaries or create permission, policy, decision, reaction, memory write, CLI,
SQLite, sentence-type, or schema capability.

Impact:

Package version becomes `0.4.1`; `SCHEMA_VERSION` remains
`genus.foundation.v0.0.1`. `passive_foundation_boundary` remains spec-known but
is not emitted until an explicit passive derivation rule exists.

## Decision 0041 - v0.4.2 audits Passive Boundary Relevance boundaries

Decision:

v0.4.2 adds no capability. It audits the v0.4.1 passive Boundary Relevance
runtime for descriptive-only summary wording, neutral boundary questions,
non-prioritizing relevance labels, report-lineage mirroring, and continued
non-emission of `passive_foundation_boundary`.

Reason:

Boundary Relevance sits close to future permission and decision semantics.
GENUS must prove that the new passive layer remains descriptive before any
later boundary work begins.

Impact:

Package version becomes `0.4.2`; `SCHEMA_VERSION` remains
`genus.foundation.v0.0.1`. No new runtime artifact, CLI command, SQLite table,
sentence type, permission, policy result, decision, reaction, memory write,
worker, LLM, GraphDB, or RuntimeShape is introduced.

## Decision 0042 - v0.4.3 aligns contracts and boundary wording

Decision:

v0.4.3 adds no capability. It aligns `ARTIFACT_CONTRACTS.md`,
`BUILD_RULES.md`, README wording, public function-cell contracts, passive
Boundary Relevance payload exclusions, and passive transition question wording
with the active v0.4.2 runtime.

Reason:

GENUS requires governance documents and runtime behavior to describe the same
artifact system. Active runtime artifacts must not remain "planned" in
contracts, and watched wording such as `evaluate` must not remain in runtime
questions when safer descriptive wording is available.

Impact:

Package version becomes `0.4.3`; `SCHEMA_VERSION` remains
`genus.foundation.v0.0.1`. No new runtime artifact, CLI command, SQLite table,
sentence type, permission, policy result, decision, reaction, memory write,
worker, LLM, GraphDB, or RuntimeShape is introduced.
