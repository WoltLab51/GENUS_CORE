# GENUS Presence and SelfState Review

Status: review document only. No runtime capability is introduced.

Purpose: examine whether GENUS needs a presence/self-state architecture, how it
relates to consciousness-like functions, and which boundaries keep the concept
technical and governed.

References:

```text
docs/reviews/GENUS_EFFICIENCY_METHOD.md
docs/reviews/GENUS_KERNEL_REPO_LEARNING_MAP.md
docs/kernel/GENUS_KERNEL_STCT_PROTOTYPE_SPEC.md
docs/vocabulary/kernel.md
```

## Executive Summary

GENUS may need consciousness-like functional ingredients: state, attention,
continuity, boundary awareness, self-description, inhibition, and presence.

This does not justify a consciousness claim.

Safe framing:

```text
GENUS is not claimed to be conscious.
GENUS does not have asserted subjective experience.
GENUS may later maintain governed self-state and presence artifacts.
```

Recommended concepts:

```text
GENUS_SELF_STATE = boundary-aware system state about GENUS itself
GENUS_PRESENCE = interaction-level coherence, attention, and expression
```

These are future spec concepts only, not active runtime artifacts.

## Why This Matters

As GENUS becomes more live, efficient, and multi-layered, it needs a way to
answer technical questions such as:

```text
What do I currently know?
What is uncertain?
Which boundary applies?
Which capability would be relevant?
Which commission, if any, is active?
What must remain forbidden?
What should be shown to the user now?
```

Without such a layer, GENUS may appear alive through language while lacking a
governed account of its own current limits.

## Consciousness Boundary

Forbidden claims:

```text
GENUS is conscious.
GENUS feels.
GENUS wants.
GENUS has subjective experience.
GENUS has rights or inner will by architecture alone.
```

Allowed technical claims:

```text
GENUS can maintain state.
GENUS can track attention.
GENUS can know active boundaries.
GENUS can describe uncertainty.
GENUS can expose why it stops.
GENUS can present coherent interaction state.
```

Boundary law:

```text
consciousness-like function != consciousness claim
presence != autonomy
self-state != self-will
```

## Layer Map

Presence and SelfState sit above CORE and KERNEL:

```text
Constitution
-> GENUS_CORE

-> Attention / SelfState
-> Capability Dimensions
-> Cells

```

CORE and KERNEL remain foundation/kernel layers. Presence must not rewrite
foundation evidence or kernel boundaries.

## SelfState

Future `SelfState` should be a governed snapshot of system-facing state, not a
personal self.

Candidate content:

```text
active_state_ref
known_uncertainties
active_boundaries
available_capability_refs
active_commission_ref
forbidden_effects
attention_refs
trace_refs
```

Not role: memory, identity soul, desire, will, decision, permission, action, or
world truth.

SelfState must be reconstructable from governed artifacts and must not become
a hidden prompt-only belief.

## Presence

Future `Presence` should describe how GENUS appears coherent and live in an
interaction.

Allowed role:

```text
surface attention
interaction continuity
tone selection
user-facing explanation
current limitation disclosure
handoff between capability surfaces
```

Forbidden role:

```text
permission
decision
memory write
reaction
external action
autonomous goal
boundary override
```

Presence may use character/interface language later, but it must remain backed
by state, trace, and boundaries.

## Attention

Attention is the bridge between efficiency and presence.

It should select a small hot set from cold and warm artifacts:

```text
relevant meaning refs
current state refs
active constraint refs
open uncertainty refs
capability refs
recent trace refs
```

Attention must not mean desire, goal, priority to execute, or permission.

## Terms To Avoid Or Remap

| Risky term | Safer GENUS term |
| --- | --- |
| desire | relevance / requested objective |
| will | no concept |
| emotion | tone / affect label, not feeling |
| instinct | hot path rule |
| self | SelfState / boundary state |
| consciousness | presence-like function |
| intention | intent or commission objective |

These safer terms still require future vocabulary before runtime use.

## Organ And Commission Boundary

Presence must not cause action by itself.

Later active flow may be:

```text
Organ -> Commission -> AgentInstance -> Trace -> Report
```

Boundary:

```text
No agent without commission.
No commission without organ boundary.
No organ without CORE/KERNEL grounding.
Presence cannot create commission.
SelfState cannot authorize action.
```

## Compatibility With Efficiency Method

`GENUS_EFFICIENCY_METHOD.md` proposes Governed Semantic Compilation:

```text
Interpret rarely.
Operate structurally.
Escalate only on uncertainty, novelty, risk, or ambiguity.
```

Presence and SelfState should use the same method. They should operate through
small structured refs rather than broad natural-language context.

## Final Recommendation

Treat Presence and SelfState as important future architecture concepts, but
keep them review-only until Internal Language and MeaningObject boundaries are
defined.

Do not implement Presence, SelfState, AttentionState, Character, Agent,
RuntimeCell, Organ, Commission, Memory, Worker, or LLM integration from this
review.
